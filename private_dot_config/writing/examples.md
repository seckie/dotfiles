### 資料A: 技術的な利用手順の README

- 用途: 利用者が導入・設定・実行し、開発者がローカルで確認するための案内。
- 著者: 本人の執筆との申告。AI の関与の有無は未確認。
- 根拠の位置と観察:
  - 冒頭: 機能を体言止めの短い紹介で示す。
  - 準備の節: 番号付き手順に、操作、条件、理由、参照先を添える。
  - 設定・入力項目の表: 項目の説明、既定値、必須性を揃える。複雑な項目は複数文で補足する。
  - 動作の節: 番号付きリストで処理の順序と分岐を説明する。
  - 開発の節: 実行例と説明を近接させ、詳細は別文書へ参照する。
- 用途への依存: 表・コード例・番号付き手順は実装や運用を説明する用途に適しており、あらゆる文書への適用は未確認。

### 資料B: 社内向けガイドライン

- 用途: 技術者に期待する行動と、守るべき規範・推奨事項の提示。
- 著者: 本人の執筆との申告。AI の関与の有無は未確認。
- 根拠の位置と観察:
  - 冒頭: 目的と背景を示し、略称を定義する。
  - 規範の各節: 禁止・義務・推奨を分類し、要求の強さを明示する。
  - 遵守事項の各項目: 短い原則に、理由や具体的な行動の箇条書きを続ける。
  - 推奨事項: 選択肢や対象別の具体策を並べる。理由を先に示す例もある。
  - 参考情報: 出典からの引用と、読者に求める行動を書き分ける。引用そのものは文体の根拠にしない。
- 用途への依存: 強い語尾や要求レベルの表示は規範文書の役割に沿っている。一般的な説明文で同じ強さが適切とは限らない。
